# 2028届部委直属事业单位招聘雷达（增强版，无大模型费用）

监控 **22个公开信息源**，覆盖工信部、科技部、市场监管总局、中科院和中国地震局。每周一北京时间09:21通过 GitHub Actions 抓取招聘公告链接并更新 GitHub Pages。**无需 OpenAI API Key，不消耗 ChatGPT token**。新公告才开 GitHub Issue 通知，不对旧公告反复推送。首次执行建立基线。

## 一、部署

1. 在 GitHub 新建公开仓库，比如 `recruit-watch`，把这个 ZIP 的 `recruit_watch/` **里面的所有文件**放在仓库根目录（包括隐藏目录 `.github/`）。
2. `Settings → Actions → General → Workflow permissions` 勾选 **Read and write permissions**，保存；GitHub 组织仓库可能不允许。
3. `Actions → Weekly recruitment watch → Run workflow` 手动执行一次。初次运行保存已有公告但不创建 Issue。
4. `Settings → Pages → Build and deployment → Deploy from a branch`，选择 `main` 和 `/docs`。网站通常位于 `https://你的用户名.github.io/recruit-watch/`。
5. `Watch → Custom → Issues` 订阅 Issue，且确认 GitHub 邮件通知已开启。

提示：GitHub Actions 的定时任务可能延迟、跳过，公开仓库长期不活跃时可能自动停用；不能取代报名期间的人工核查。

### 来源可靠性和覆盖范围

- `sources.json` 标注 `kind: recruitment` 的是招聘专栏，效果一般最好；`kind: announcements` 是混合公告栏；`kind: homepage` 只是**官网首页兜底**。官网首页可能不展示招聘信息，不能视为完整监控。
- 个别官网网址是域名入口，实际招聘栏目需要进一步核实；无法访问会在网页「来源状态」显示失败，而不是悄悄标记为“无招聘”。
- 多数站点只检索页面上直接出现的 `<a>` 链接，不自动读取 JS 动态接口、不跨页遍历、不下载 PDF/Excel 岗位表。**因此不能保证覆盖所有招聘，也无法判断具体毕业届别、北京户口、是否入编。**
- 排除“采购/招标/招生”等明显无关词；招聘流程公告（笔试成绩、面试、公示等）在网页默认隐藏，可以选择显示。只有新增招聘公告会产生 Issue。
- “专业匹配关键词”不是专业资格审核；“2028届线索”也不是已确认能报；所有结论必须回到原公告和岗位表。

## 三、频率设置

修改 `.github/workflows/weekly.yml` 的 cron，时间基于 UTC：
- `21 1 * * 1`：每周一北京时间09:21（默认）
- `21 1 1 * *`：每月1日北京时间09:21
- `21 1 * * *`：每天北京时间09:21

建议：2026年底至2027年7月每月一次，2027年8—11月每周一次，临近重要报名截止时人工加查。首次配置时可以直接用默认每周一次，因为不会消耗模型 token。

## 四、本地运行

```bash
pip install -r requirements.txt
python monitor.py
python -m http.server 8000 --directory docs
```

打开 `http://localhost:8000`。生成的数据为 `data/items.json`（累计链接）、`data/new_items.json`（本轮新增招聘链接）、`data/source_status.json`（各来源抓取状态），展示页面 `docs/index.html`。

`python monitor.py --baseline` 可以手动仅建基线、不通知（不会清理之前的数据）。

## 五、隐私和使用说明

抓取结果会提交到公开 GitHub 仓库，**勿上传任何个人身份、简历、联系方式、密码或私有材料**。本项目只浏览公开网页，不绕过验证码和访问控制、不进行高频请求；部分站点因网络、反爬或改版会抓取失败。发生失败时请查看 Actions 日志并手动访问该来源。

公告发布日期不一定能从列表识别。新发现 ≠ 新发布：网站改版或新增监控来源可能使旧公告在下一次运行才被发现。加入大量来源后可用 `--baseline` 建立基线，避免旧公告集中通知。
